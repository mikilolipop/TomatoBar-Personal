# 分类视觉的数据与呈现契约（设计，未实现）

2026-09-29 · Codex。基于 ef50b45 的手动图标选择。只定义后续实现契约，本轮不新增像素素材、不实现新存储格式或颜色选择 UI。

## 产品表现

分类仍是记录的首标签；样式是同名分类共享的展示元数据，不是新的统计分类体系。
日色块与编辑器使用同一个解析结果。周柱/月格保持现有统计编码：周柱颜色表达分类，月格深浅表达总时长，不把每一天替换成一个容易混淆分类的小插画。

- 自动：七个既有建议分类沿用当前语义；自定义分类保持稳定的自动图标与颜色。
- 手动 SF Symbol：保留用户已经选择的图标，不因引入像素素材而自动替换。
- 手动像素图案：用户从视觉选择器主动选择，分类所有记录同步改变；保存才生效，取消放弃本轮草稿。
- 未分类：空标签的显示态，固定网格/中性色，无手动样式入口。不增加“清空标签回到未分类”的选择项。
- 颜色本轮继续自动。数据契约可预留颜色，但不要借设计说明擅自新增完整颜色管理器。

后续素材规格：透明背景、统一 24×24 像素网格、静态形态、有限调色板；以整数倍最近邻缩放。
编辑器预览与日色块展示同一图案，周/月无需新增动画。图案只辅助识别，名称仍可见/可读屏，不能仅凭颜色区分类别。
素材清单维护稳定 ID、资源名、版本、中文名称及 SF fallback；资源替换可换文件，但不要复用 ID 表达不同语义。
第一批可为书本、叶子、耳机、电脑、数学、铅笔、通用标签；具体像素图由 Codex 后续交付，尚无可用素材。

## 存储：保留旧字段，另加可选展示字段

**`categoryStyles: [String: String]` 永远继续表示 SF Symbol 字符串。**
不向旧值塞 `pixel:...`、JSON 字符串或资源路径，不把已有字典值改成对象。

建议新增可选 `categoryVisuals`，仅在用户作出新样式选择时写入。示例是未来格式，不可直接灌入当前版本：

```json
{
  "categoryStyles": { "swift": "star" },
  "categoryVisuals": {
    "swift": {
      "version": 1,
      "icon": { "kind": "pixel", "id": "pixel.laptop.v1", "fallbackSymbol": "laptopcomputer" }
    }
  }
}
```

未来如明确需要手动颜色，可在单个样式内增加 `color: { "kind": "palette", "id": "sage" }`。
颜色 ID 指向稳定注册表，不存 SwiftUI.Color、不存数组下标、不存系统颜色归档对象。
当前已有建议分类颜色和 FNV 映射视为 auto-v1，冻结已发布顺序；扩展调色板不能通过更改模数重染所有旧分类。

## 读取和回退顺序

图标与颜色分别解析，某个维度失败不丢弃另一个维度。

1. 真正无标签的记录：直接使用未分类样式。当前字面标签“未分类”与显示态存在同名歧义，兼容阶段继续保留现有保留名行为，不在此轮重定义统计含义。
2. 找到可识别的新 `categoryVisuals[key].icon`，资源存在：使用它。
3. 新字段缺失、版本/类型未知、资源不存在：优先使用可用的旧 `categoryStyles[key]`；其次使用新描述里的有效 fallbackSymbol；再回到自动图标。
4. 旧 Symbol 在当前 macOS 不存在时，也应回退到自动图标，最后兜底网格。用 `NSImage(systemSymbolName:accessibilityDescription:)` 判定，不把任意字符串直接交给 Image 后留下空白。
5. 颜色有有效覆盖时使用覆盖，否则走现有自动颜色；未分类一直中性。新图案失效不改变分类、时长或统计。

元数据容错仅限展示字段：缺失/null → 无覆盖；单个坏条目 → 该条回退，不使整份 sessions.json 变成“损坏”。
旧 phase、records、日期等承重字段继续严格解码，不用 `try?` 包住整个 FocusState。
`kind` / `version` 用可容忍未知值的表示；保留未识别样式的原始 payload，直到用户主动替换/清除，避免无关记录编辑顺手删除未来版本元数据。
这种保留只针对小型展示 payload，无需引入外部文件格式或迁移脚本。

## 分类名与键的一致性

保持旧键，不在加载时整体 rekey。后续统一使用同一个分类名解析方法：去两端空格 → 按现有 `caseInsensitiveCompare` 匹配已知标签 → 使用其既有显示写法。
写样式时从**最终规范化的首标签**得到兼容的小写键，而不是从保存前输入框的拼写得到键。

读取旧覆盖：先精确小写键，后按相同的 case-insensitive 语义查别名；若存在多个候选，优先精确键，否则以稳定排序确定赢家并保留其余项。
例如 `Straße` 和 `STRASSE` 比较相等但 lowercased 不相同（BACKLOG P12），不能仅靠两个 lowercased 断言身份相同。
编辑器预览、保存、图表和未来颜色覆盖必须共用解析器。自动哈希应以已选定的规范显示名为输入，不能在预览与保存之间各自取不同拼写。

不承诺“任意两个自定义分类必有不同图标”：有限图标集一定存在哈希碰撞；手动选择提供调整手段。
未来真正的全局分类重命名需要单独的样式转移事务，不能把修改某条记录首标签等同于全局重命名。

## 写入、恢复自动、兼容旧版

- 打开旧文件：仅在内存把旧字符串解析为 system-symbol 选择；不批量迁移、不重写字符串，不需要数据脚本。
- 用户选像素图：只写该分类的新 icon 描述，保留原有 categoryStyles 字符串作为旧版兼容/资源缺失回退。
- 用户改选 SF Symbol：更新该分类的旧字符串并移除该分类的新 icon 覆盖，保留可选颜色设置。
- “恢复自动图标”：显式删除该分类的新 icon 与旧 SF override，避免旧覆盖复活；只清图标，不清其他分类或颜色。
- 保存采用**本轮实际编辑的分类键增量**（包括显式删除），合并到最新 state 后一次原子落盘；不能提交打开编辑器时抓取的全量样式快照（BACKLOG P13）。
- 删除某条记录不删除分类样式；之后重用分类仍保留用户选择。自动清理孤立样式不是本轮目标。
- 旧应用可以忽略新字段并继续用旧字符串，但旧版重新保存会丢弃它不认识的新字段；**不能承诺降级写入后像素选择仍保留**。若日后要求无损降级写入，需另行设计存储层，而非改变旧字符串格式。

## 后续实现验收

无 categoryStyles 的旧文件、现有 SF 覆盖、缺新字段/null、单个坏样式、未知 version/kind、缺像素资源、无效 Symbol 均可读且计时不被锁死。
Swift/swift、Straße/STRASSE、空标签分别检查预览/保存/重启一致；所有三处渲染共用解析结果。
取消、保存失败、恢复自动、两编辑器先后保存、删除最后一条分类记录都要覆盖。
像素资产接入前由 Codex 交付素材与视觉稿；Claude Code 可按本契约实现，不能把此文视为新格式已经可用。
